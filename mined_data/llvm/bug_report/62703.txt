I wanted to try out a different, shorter solution i found using rotates:
```wat
  (func (export "bswap") (param i32) (result i32)
    (i32.or
    (local.get 0)
    (i32.const 0x00FF00FF)
    (i32.and)
    (i32.rotr (i32.const 8))

    (local.get 0)
    (i32.const 0xFF00FF00)
    (i32.and)
    (i32.rotl (i32.const 8))))
```

However when i write the C++ version of it:
```c++
inline u32 bswap(u32 x) {
    return __builtin_rotateleft32((x & 0xFF00FF00), 8) 
        | __builtin_rotateright32((x & 0x00FF00FF), 8);
  }
```

It will still be replaced with the longer version from before.
This seems to be a general issue with rotates of masked inputs, since a single rotate will also be "optimized" into a way longer version.
For example:
```c++
inline u32 bswap(u32 x) {
  return __builtin_rotateleft32((x & 0xFF00FF00), 8);
}
```

Turns into:
```wat

    i32.and

    i32.shl
    local.get 0
    i32.const 24
    i32.shr_u
    i32.or)
```
instead of:
```wat
  (func (;240;) (type 6) (param i32) (result i32)
    local.get 0
    i32.const -16711936
    i32.and
    i32.const 8
    i32.rotl))
```

If i disable optimizations for this function with `[[clang::optnone]]`, it will keep the roate.

Comment by pmatos: @HailToDodongo Thanks for the report. I was nerd-snipped by this one.

The reason you are seeing an expansion of the rotate is due to a sequence of optimizations that fail to recognize in the end a rotate. 

Clang transforms rotates into funnel shifts (fshl). Funnel-shifts are like rotate when the first two arguments are the same (see: https://llvm.org/docs/LangRef.html#llvm-fshl-intrinsic).

However, Clang optimizes the funnel shift and generates the IR:
```
define linkonce_odr noundef i32 @_Z4testj(i32 noundef %0) #0 comdat {
  %2 = and i32 %0, 65280
  %3 = tail call i32 @llvm.fshl.i32(i32 %2, i32 %0, i32 8)
  ret i32 %3
}
```

This is correct from Clang's PoV. LLVM doesn't generate a rotate because the first and second arguments are not the same and therefore it expands it. I will try to understand better where the optimization is happening in Clang and if there's anything we can do about it.

Comment by pmatos: Proposal for a fix in https://reviews.llvm.org/D150670

Generated code for the original example above:
```
bswap:                                  # @bswap
	.functype	bswap (i32) -> (i32)
# %bb.0:                                # %entry
	local.get	0
	i32.const	16711935
	i32.and
	i32.const	8
	i32.rotr
	local.get	0
	i32.const	-16711936
	i32.and
	i32.const	8
	i32.rotl
	i32.or
                                        # fallthrough-return
	end_function
```
