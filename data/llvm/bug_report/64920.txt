Issue Title: [analyzer] ArrayBound constraint assumption and size type inconsistency within DynamicExtent
Original Post: Size type inconsistency can be observed in several places:
https://github.com/llvm/llvm-project/blob/bcabaa5590052d1e9f78522a1f45621fe1a95b06/clang/test/Analysis/flexible-array-members.c#L127-L131
The same API gives different result types, which can cause problems when using
https://github.com/llvm/llvm-project/blob/bcabaa5590052d1e9f78522a1f45621fe1a95b06/clang/test/Analysis/array-bound-v2-constraint-check.c#L78-L84
as a base, the following example
```cpp
void symbolic_longlong_and_int0(long long len) {
  char *a = malloc(5);
  (void)a[len + 1]; // no-warning
  // len: [-1,3]
  clang_analyzer_eval(-1 <= len && len <= 3); // expected-warning {{TRUE}}
  clang_analyzer_eval(0 <= len);              // expected-warning {{UNKNOWN}}
  clang_analyzer_eval(len <= 2);              // expected-warning {{UNKNOWN}}
}
```
With `DynamicMemoryModeling` turned on, the second warning does not
hold anymore, `0 <= len` will be reported as `TRUE` which might not be expected.

For `extent` or `count` like quantities, `ASTContext::getSizeType()` might be more suitable than `SValBuilder::getArrayIndexType()`. We might need to keep consistent with those APIs like (not complete):
1. `getDynamicElementCount`
2. `getDynamicExtentWithOffset`
3. `setDynamicExtent` the `Size` arg
4. `PlacementNewChecker::getExtentSizeOfNewTarget`

For `ArrayBoundV2` types of operands should be consistent to avoid `-Wsign-compare` errors.

See also https://reviews.llvm.org/D158499 which started this issue.
