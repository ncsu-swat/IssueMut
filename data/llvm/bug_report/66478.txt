Issue Title: [OMPT] `data_op[_emi]` callback is not or incorrectly dispatched on device to device operations depending on vendor
Original Post: ## Description

Recently, LLVM has added support for parts of the OMPT interface for OpenMP target directives and functions. While testing, I noticed that there is an issue with `ompt_callback_target_data_op` and the external monitoring interface variant on NVIDIA GPUs specifically. On AMD GPUs, the dispatched callbacks are correct, but seem confusing when compared to the output of `LIBOMPTARGET_DEBUG=-1`

On NVIDIA GPUs, the callback is only dispatched when allocating / freeing memory and for operations between host and device. Device to device operations do not dispatch a callback.

On AMD GPUs, everything seems fine. However, the runtime dispatches two callbacks ( device->host, host->device ) even though the runtime reports a direct transfer between both devices.

## Reproducer

The reproducer is attached down below. In general, it uses the OMPT interface used in the LLVM tests, with slight modifications to not crash on `omp_target_[...]` function calls since they do not set `target_task_data` with a pointer. In addition, I have removed the condition that transfers from a device to the same device are invalid, since it is possible from the runtime side. 

Here's the output of the reproducer for both on a system with four NVIDIA GPUs and a system with a single AMD GPU. Unfortunately, I don't have access to a system with more than one AMD GPU right now, since ours is currently broken. For the tests with AMD GPUs, I used the recently released AOMP 18.0-0.

## Description

Recently, LLVM has added support for parts of the OMPT interface for OpenMP target directives and functions. While testing, I noticed that there is an issue with `ompt_callback_target_data_op` and the external monitoring interface variant on NVIDIA GPUs specifically. On AMD GPUs, the dispatched callbacks are correct, but seem confusing when compared to the output of `LIBOMPTARGET_DEBUG=-1`

On NVIDIA GPUs, the callback is only dispatched when allocating / freeing memory and for operations between host and device. Device to device operations do not dispatch a callback.

On AMD GPUs, everything seems fine. However, the runtime dispatches two callbacks ( device-&gt;host, host-&gt;device ) even though the runtime reports a direct transfer between both devices.

## What would I expect?

For NVIDIA GPUs, we should see the same results as for the AMD GPUs. Regarding the AMD GPUs, I would expect to see a direct transfer between GPUs reported by the OMPT interface. However, this assumes that this is in fact the case. `LIBOMPTARGET_DEBUG` seems to indicate that, but I'm not able to verify it right now. 

As for AOMP 18.0-0, this probably also affects the device tracing interface as well since the trace records are based on the dispatched callbacks.

Since there's no `ompt_target_data_transfer_tofrom_device` (within `ompt_target_data_op_t` enum) or something other that conveys the meaning of inter-device data exchange we decided to arbitrarily choose one of `ompt_target_data_transfer_to_device (=2)` and `ompt_target_data_transfer_from_device (=3)` (we chose the latter).
