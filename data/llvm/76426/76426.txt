Comment by kawashima-fj: I took a look a bit.

Stack trace: https://godbolt.org/z/dY7h77KKr
Failed at `llvm::AArch64TargetLowering::getRegisterByName`.

[Rejecting a `__asm__("x15")` global register variable without `-ffixed-x15` seems intentional](https://github.com/llvm/llvm-project/blob/llvmorg-17.0.6/llvm/lib/Target/AArch64/AArch64ISelLowering.cpp#L9679).

[Clang has checks to validate the register name](https://github.com/llvm/llvm-project/blob/llvmorg-17.0.6/clang/lib/Sema/SemaDecl.cpp#L7929). Especially, [there is a check to validate the register name used for global register variables](https://github.com/llvm/llvm-project/blob/llvmorg-17.0.6/clang/lib/Sema/SemaDecl.cpp#L7959). [X86 overrides the `validateGlobalRegisterVariable` function](https://github.com/llvm/llvm-project/blob/llvmorg-17.0.6/clang/lib/Basic/Targets/X86.h#L784) and can emit a appropriate error message but AArch64 doesn't. If AArch64 also overrides the function and validates correctly, a user can see a appropriate error message ("register '%0' unsuitable for global register variables on this target"). However, we may not be able to see the `-ffixed-x15` flag in this function.


Just FYI, [GCC shows a warning message (warning: call-clobbered register used for global register variable) but does not make it an error](https://godbolt.org/z/sce6d8Tnc).
