Issue Title: GCC compatibility: Raw strings in C mode
Original Post: GCC in -xc -std=gnuNN mode accepts C++11 raw strings. https://godbolt.org/z/qoM55qqfz
```c++
// Type your code here, or load an example.
const char * square(void) {
    return R"(a"b"c)";
}
```
Perhaps Clang should too?

(Ideally, I'd like to see that feature present in C3x or something, but that's far off. It would technically break existing source code that #defines R to [something funny](https://godbolt.org/z/EWYa3hvhh).)

Comment by Sirraide: I was thinking we could consider supporting it if `R` is not `#define`’d, but that runs into some annoying edge cases:
```c
#define FOO R"(")"
#define R "bar"

FOO // What does this expand to?
```

Or alternatively:
```c
#define R "bar"
#define FOO R"("
#undef R

FOO // What does this expand to?
```
As I see it, what `FOO` would expand to here would end up depending on where the macro is defined, not where it is used, which runs contrary to how macros normally work—that or we’d have to treat `R"(")"` and `R"("` e.g. as an annotation token, because one of those is always an invalid string literal; which one depends on whether we allow raw strings or not. That sounds doable in theory, but I’m not sure it’s worth the hassle of making sure we don’t explode as soon as you try and do anything funny with it...
